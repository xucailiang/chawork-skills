# 管理后台 — 员工管理功能设计

## 1. 背景

当前管理后台（`/admin`）支持技能导入和技能/员工列表查看+删除，但缺少员工的完整管理能力：

- 无法新增员工
- 无法编辑员工（修改名称、描述、提示词、技能组合）
- 无法管理员工的技能组合（添加/移除技能）

员工 = 技能组合 + 系统提示词，是面向 ChaWork 桌面端用户的"AI 角色模板"。管理员需要在后台灵活创建和配置员工。

## 2. 需求

### 2.1 员工列表增强

在现有 EmployeeTable 基础上增加：
- 「新增员工」按钮
- 每行增加「编辑」操作（除了现有的「删除」）
- 展示员工的技能组合概览

### 2.2 新增员工

通过表单创建新员工，需要填写：

| 字段 | 必填 | 说明 |
|------|------|------|
| ID | 是 | 唯一标识，英文 kebab-case（如 `frontend-dev`） |
| 名称 | 是 | 显示名称（如 `前端开发工程师`） |
| 描述 | 否 | 简介（如 `精通 React/Vue/TypeScript 的前端开发角色`） |
| 类型 | 是 | `ordinary`（默认）或 `dream` |
| 系统提示词 | 是 | Markdown 格式的 prompt，定义员工角色和行为 |
| 技能组合 | 否 | 从已有技能列表中多选 |
| 标签 | 否 | 自定义标签，用于搜索和分类 |

### 2.3 编辑员工

打开编辑表单，可修改：
- 名称、描述、类型、标签
- 系统提示词（Markdown 编辑器）
- 技能组合（添加/移除技能）

### 2.4 技能组合管理

员工编辑/创建时的技能选择器：
- 展示 Hub 中所有已入库的技能列表
- 支持搜索筛选
- 多选模式（勾选/取消勾选）
- 已选技能显示在表单上方，可单独移除

## 4. 组件设计

### 4.1 新增组件

```
web/components/admin/
├── EmployeeTable.tsx          # existing — 增加「新增」「编辑」按钮
├── EmployeeForm.tsx           # new — 新增/编辑员工表单
├── SkillPicker.tsx            # new — 技能多选器
├── PromptEditor.tsx           # new — 提示词文本编辑器
├── ImportPanel.tsx            # existing
└── SkillTable.tsx             # existing
```

### 4.2 EmployeeForm

员工创建/编辑的主表单组件。

```tsx
interface EmployeeFormProps {
  mode: "create" | "edit"
  initialData?: EmployeeDetail        // 编辑时传入
  onSave: () => void                   // 保存成功后回调
  onCancel: () => void                 // 取消回调
}
```

- 创建模式：ID 字段可编辑
- 编辑模式：ID 字段只读，从 API 加载完整数据（含 prompt_md）

### 4.3 SkillPicker

技能多选器组件。

```tsx
interface SkillPickerProps {
  selected: string[]                   // 已选技能 ID 列表
  onChange: (ids: string[]) => void    // 选择变更回调
}
```

- 从 `GET /api/v1/skills?limit=500` 加载所有技能
- 支持关键词搜索（本地过滤 name + description_zh）
- 列表项显示：勾选框 + 技能名 + 职业分类
- 已选技能以标签形式展示在上方，可单独移除

### 4.4 PromptEditor

提示词编辑器。

```tsx
interface PromptEditorProps {
  value: string
  onChange: (val: string) => void
}
```

- 纯文本 textarea，等宽字体
- 足够高度（至少 300px）
- 后续可升级为带 Markdown 预览的编辑器

## 5. 页面路由

### 5.1 方案选择

不新增独立路由页面，而是在现有 `/admin` 页面内用**弹窗（Dialog）**方式打开表单。理由：
- 管理后台是单页面，Tab 切换已足够
- 弹窗避免路由跳转，保留列表状态
- 交互更轻量

### 5.2 交互流程

```
员工 Tab
  ├── 点击「新增员工」→ 打开 EmployeeForm 弹窗（create 模式）
  │     ├── 填写表单 → 点击「保存」→ POST /employees → 关闭弹窗 → 刷新列表
  │     └── 点击「取消」→ 关闭弹窗
  └── 点击某行「编辑」→ 打开 EmployeeForm 弹窗（edit 模式，预加载数据）
        ├── 修改表单 → 点击「保存」→ PUT /employees/:id → 关闭弹窗 → 刷新列表
        └── 点击「取消」→ 关闭弹窗
```

## 6. API 调用

| 操作 | API | 说明 |
|------|-----|------|
| 加载技能列表 | `GET /skills?limit=500` | SkillPicker 需要 |
| 加载员工详情 | `GET /employees/:id` | 编辑时加载（含 prompt_md） |
| 创建员工 | `POST /employees` | 表单提交 |
| 更新员工 | `PUT /employees/:id` | 表单提交 |
| 删除员工 | `DELETE /employees/:id` | 列表操作（已有） |

创建请求体：
```json
{
  "id": "frontend-dev",
  "name": "前端开发工程师",
  "description": "精通 React/Vue/TypeScript 的前端开发角色",
  "kind": "ordinary",
  "prompt_md": "你是一名资深前端开发工程师...",
  "skill_ids": ["web-artifacts-builder", "webapp-testing", "frontend-design"],
  "tags": ["开发", "前端"]
}
```

更新请求体（只传要修改的字段）：
```json
{
  "name": "新名称",
  "prompt_md": "更新后的提示词...",
  "skill_ids": ["skill-a", "skill-b"]
}
```
